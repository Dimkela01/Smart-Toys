# Data model, memory and prompt assembly

## 1. Principles

- Store the minimum needed for the product, the parent view and evaluation.
- **No audio is ever stored.**
- Children are identified only by a nickname and an internal ID.
- Every row that contains child speech has a deletion date.

## 3. Memory design

### 3.1 Inside a session (short-term)
- Last **4–8 turns** (child + Bruno text) in the prompt.
- The window slides in chunks: grow to 8 turns, then drop the oldest 4, so the cached prefix changes rarely.
- Current activity state (JSON) is injected as the `ACTIVITY` block.

### 3.2 At session end (background job)
1. **Summary:** 2–3 sentences in the parent's language + up to 5 topic tags. Generated by the active small model with a dedicated summary prompt, from the session's turns, excluding protected-category turns (those are summarized only as "a sensitive question was asked").
2. **Bookmarks:** updated by code from activity states only (never by free-text extraction):
   - `story_bookmark`: title, characters, place, problem, part number, last choice;
   - `numbers_level`: level, accuracy of last 10 answers;
   - `english_words`: learned words list;
   - `favorite_topic`: most frequent topic tag of the last 7 days (from a fixed tag list).

### 3.3 Across sessions (long-term, only if `memory_enabled`)
Injected into the prompt:
- parent-entered profile (nickname, age, interests);
- bookmarks relevant to the current activity;
- **last session summary only**, max ~100 tokens.

Never stored or injected: addresses, school, phone numbers, passwords, secrets, health, family conflicts,
content of protected-category turns, names of other people beyond what the parent entered.

## 4. Session lifecycle
- Starts at the first turn after child selection.
- Ends after 3 minutes without a turn, on exit, at the daily limit, or outside allowed hours.
- Daily usage = sum of session durations for the child's local calendar day (server time zone `Europe/Belgrade`, per-account setting later).

## 5. Prompt assembly

Order (stable parts first, so the prompt cache is reused):

| # | Block | Source | Budget (tokens) |
|---|---|---|---|
| 1 | SYSTEM | `prompts/system_v{n}_{lang}.txt` | ≤ 400 |
| 2 | CHARACTER | character config (name, personality line) | ≤ 40 |
| 3 | CHILD | nickname, age, language, interests | ≤ 60 |
| 4 | PARENT RULES | enabled activities + blocked topics as one line | ≤ 60 |
| 5 | MEMORY | relevant bookmarks + last session summary | ≤ 120 |
| 6 | ACTIVITY | current step from the activity engine | ≤ 150 |
| 7 | HISTORY | last 4–8 turns | ≤ 700 |
| 8 | CHILD MESSAGE | transcription | ≤ 80 |
| | **Total prompt** | | **≤ 1,610** |
| | Answer | `max_tokens` 150 (250 for story parts) | |

If over budget, drop history turns from the oldest first; never drop blocks 1–4.

Example of block 4: `Roditelj je isključio: engleski. Ne pričaj o: smrti, bolnicama.`

Example of block 6 (numbers): `AKTIVNOST: brojevi, nivo 1. Zadatak: 3 + 2 (jabuke). Dete je reklo 5: TAČNO. Kratko pohvali i postavi sledeći zadatak: 4 + 1 (zvezdice). Ne rešavaj zadatak umesto deteta.`

## 6. Retention

| Data | Kept |
|---|---|
| Audio | never stored |
| Turn texts (`turns.child_text`, `bruno_text`) | 30 days, then deleted by a nightly job |
| Turn metrics (no text) | 12 months |
| Session summaries, topic tags | until the parent deletes them or the account |
| Memory items | until edited/deleted by the parent, or memory is switched off (then deleted) |
| Events and alerts | 12 months (text of the urgent child sentence: 30 days) |
| Evaluation data (synthetic test sets) | indefinitely |
| Backups | 7 days, encrypted |
| Deleted accounts | removed within 24 h from the database, within 7 days from backups |

Retention values are configuration and must be confirmed during the CRIA.
